2. INTERNAL TICK SCHEMA (NORMALIZED FORMAT)
=====================================================================

Every WS tick MUST be normalized to this dict before sending to Kafka:

{
  "symbol": "RELIANCE",
  "exchange": "NSE",
  "time": "2025-12-07T09:21:32.123+05:30",
  "ltp": 2710.25,
  "volume": 200,
  "bid": 2709.9,
  "ask": 2710.4
}

Rules:

- symbol:
  - Short, clean: "RELIANCE", "HDFCBANK", "NIFTY", "BANKNIFTY".
  - Derived from config instruments like "NSE:RELIANCE-EQ".
- exchange:
  - Example: "NSE".
- time:
  - ISO 8601 string with timezone, e.g. datetime.now().astimezone().isoformat().
  - Prefer broker timestamp if reliable.
- ltp:
  - Last traded price as float.
- volume:
  - Incremental trade size or 0 if not available.
- bid / ask:
  - If not provided, set to 0.

All Kafka messages on topic "ticks.raw" MUST follow this schema.

3.5 internal/websocket/angel_ws_client.py
------------------------------------------------------------

Purpose:
- Handle WebSocket connection to Angel.
- Subscribe to configured instruments.
- Receive raw ticks.
- Normalize them.
- Forward them to a provided tick_handler callback.

Class: AngelWSClient

Attributes:
- cfg: dict
- logger: logging.Logger
- tick_handler: Callable[[dict], None]
- token_mapping: dict[int, tuple[str, str]]  # token -> (symbol, exchange)
- angel_session / angel_ws: underlying SmartAPI WS client
- connected: bool

Methods (each with a comment block explaining flow):

- __init__(cfg, logger, tick_handler, token_mapping)
  - Store parameters.
  - Prepare for connection (but don’t connect yet).

- connect() -> None
  - Use smartapi_login.create_angel_session() to get a session.
  - Initialize WS client from the session.
  - Register WS callbacks (on_open, on_message, on_error, on_close).
  - Start or prepare WS connection (depending on SDK style).

- disconnect() -> None
  - Close the WebSocket connection cleanly.
  - Update connected flag.

- subscribe(instruments: list[str]) -> None
  - Translate instrument identifiers (e.g., "NSE:RELIANCE-EQ") to tokens or whatever Angel expects.
  - Send subscription request over WS.

- run_forever(shutdown_event: threading.Event) -> None
  - Start/enter WS event loop.
  - Continue receiving messages until shutdown_event is set.
  - For each WS tick message:
    - Normalize it (see below).
    - Call tick_handler(normalized_tick).
  - If WS error or disconnect occurs:
    - Log the error.
    - Raise an exception to let the outer reconnect loop handle it.

Tick Normalization (in a helper method inside this class):

- normalize_tick(raw_msg: Any) -> Optional[dict]
  - Extract instrument token or identifier.
  - Map token → (symbol, exchange) using token_mapping.
  - Extract:
    - last traded price
    - incremental volume if available
    - bid/ask if available
    - timestamp
  - Build dict matching the internal Tick schema.
  - Return tick dict.
  - If mapping fails or message invalid:
    - Log warning.
    - Return None.

Ignore:
- Heartbeats / pings / non-tick messages.

4. MAIN ENTRYPOINT – python_feed/main/main.py
=====================================================================

Purpose:
- Wire everything.
- Control lifecycle, reconnect loop, and shutdown.

Function: main()  (with comment block explaining full flow)

Steps:

1) Load config:
   - Use internal.config.config_loader.load_config("python_feed/config/ws_feed_config.json").

2) Setup logging:
   - Use log.logger_setup.setup_logging(config["log"]["level"], config["log"]["file"]).
   - Get a logger instance (e.g., logger = logging.getLogger("ws_feed_service")).

3) Initialize KafkaTickProducer:
   - From internal.kafka.kafka_producer.KafkaTickProducer with config["kafka"].

4) Build instruments + token mapping:
   - For now:
     - build list of instrument strings from config["symbols"]["indices"] + ["equities"].
     - token mapping can be stubbed or manually defined (TODO with SmartAPI dump later).

5) Create shutdown_event = threading.Event().

6) Create HealthMonitor:
   - Using internal.health.health.HealthMonitor(logger, config["health"]["print_stats_interval_sec"]).

7) Define tick_handler(tick: dict):
   - Comment block: explain that this is the central path from WS to Kafka.
   - Call health_monitor.on_tick()
   - Call kafka_producer.send_tick(tick)

8) Create AngelWSClient:
   - angel_client = AngelWSClient(cfg=config, logger=logger, tick_handler=tick_handler, token_mapping=token_mapping)

9) Register signal handlers:
   - For SIGINT and SIGTERM:
     - Handler sets shutdown_event.
     - Logs that shutdown was requested.

10) Reconnect loop:

   - Read backoff_seconds and max_retries from config["reconnect"].
   - Pseudocode:

     retries = 0
     while not shutdown_event.is_set():
         try:
             logger.info("Connecting to Angel WebSocket...")
             angel_client.connect()
             health_monitor.set_connected(True)

             # Loop until shutdown_event is set or WS breaks
             angel_client.run_forever(shutdown_event)

             health_monitor.set_connected(False)
             # If run_forever exited without shutdown flag, treat as error
             if not shutdown_event.is_set():
                 raise RuntimeError("WebSocket loop exited unexpectedly")

         except Exception as e:
             logger.exception("WebSocket loop crashed: %s", e)
             health_monitor.set_connected(False)
             retries += 1
             if max_retries > 0 and retries > max_retries:
                 logger.error("Max retries exceeded, exiting main loop")
                 break
             time.sleep(backoff_seconds)
             continue

     # on exit from loop
     logger.info("Shutdown requested, closing connections...")
     angel_client.disconnect()
     kafka_producer.flush()
     logger.info("Shutdown complete")

11) Call main() under the standard guard:

   if __name__ == "__main__":
       main()
