- Consumes normalized tick data from Kafka topic `"ticks.raw"`.

- Normalizes **symbol case to UPPERCASE only** and converts all timestamps to the configured timezone before truncation (no suffix/prefix trimming).

1. INPUT TICK SCHEMA (KAFKA "ticks.raw")
=====================================================================

The Python WS utility publishes normalized ticks as JSON:

{
  "symbol": "RELIANCE",
  "exchange": "NSE",
  "time": "2025-12-07T09:21:32.123+05:30",
  "ltp": 2710.25,
  "volume": 200,
  "bid": 2709.9,
  "ask": 2710.4
}

In Go, define:

// Tick represents a single normalized market tick consumed from Kafka "ticks.raw".
type Tick struct {
    Symbol   string    `json:"symbol"`
    Exchange string    `json:"exchange"`
    Time     time.Time `json:"time"`    // parsed from RFC3339 / ISO8601
    LTP      float64   `json:"ltp"`
    Volume   int64     `json:"volume"`
    Bid      float64   `json:"bid"`
    Ask      float64   `json:"ask"`
}

Behavior:
- Parse `"time"` using `time.Parse(time.RFC3339Nano, rawTimeString)`.
- If parsing fails:
  - Log a warning.
  - Skip that tick (don’t crash the service).

2. OUTPUT CANDLE SCHEMA ("candles.1m" & "indices.1m")
=====================================================================

For each symbol and minute, publish a candle with session VWAP:

Example (stock candle):

{
  "symbol": "RELIANCE",
  "time": "2025-12-07T09:21:00+05:30",
  "open": 2708.5,
  "high": 2711.0,
  "low": 2707.8,
  "close": 2710.25,
  "volume": 50000,
  "vwap": 2709.75
}

Same schema goes to `"indices.1m"` for `"NIFTY"` and `"BANKNIFTY"`.

Define:

// Candle represents a 1-minute OHLCV bar with session VWAP.
type Candle struct {
    Symbol string    `json:"symbol"`
    Time   time.Time `json:"time"`   // minute start time (truncated to minute, in configured timezone)
    Open   float64   `json:"open"`
    High   float64   `json:"high"`
    Low    float64   `json:"low"`
    Close  float64   `json:"close"`
    Volume int64     `json:"volume"`
    VWAP   float64   `json:"vwap"`
}

Note:
- This service can emit **partial candles on shutdown** if `flush_on_shutdown` is true.  
  Consumers must assume the **latest candle may be incomplete**.

9. ERROR HANDLING RULES
=====================================================================

- Tick JSON parse error:
  - Log warning with enough context.
  - Skip and continue.

- Time parse error:
  - Log warning.
  - Skip that tick.

- Kafka producer send error:
  - Log error, try to continue.
  - If fatal connection error → you may exit main and let supervisor restart.

- Kafka consumer fatal error:
  - Log error, exit main.

- On panic:
  - Prefer to recover in main, log stack trace, then exit.
